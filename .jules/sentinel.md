
## 2024-05-18 - [TOCTOU Vulnerability in File Copying]
**Vulnerability:** A Time-of-Check to Time-of-Use (TOCTOU) race condition in file copying. The app checked if the destination was a symlink using `path.is_symlink()` and subsequently called `shutil.copy2(src, dest)`. An attacker could exploit the time gap between the check and the actual write operation to swap the file with a symlink, allowing them to overwrite arbitrary files on the system since `shutil.copy2` does not inherently prevent following symlinks for writes.
**Learning:** Checking for a symlink explicitly is insufficient on its own if the file is created or written to using a function that follows symlinks. `shutil.copy2` does exactly this if `follow_symlinks=False` is not used.
**Prevention:** Avoid writing to files using operations susceptible to TOCTOU. Used a custom `_secure_copy` function that securely creates or opens the destination file using `os.open` with `O_NOFOLLOW | O_WRONLY | O_CREAT | O_TRUNC` and streams data into it using `shutil.copyfileobj`. If the destination is swapped for a symlink in the interim, the system call will fail safely with `ELOOP` (Too many levels of symbolic links). On non-POSIX systems, `shutil.copy2` with `follow_symlinks=False` should be used.
