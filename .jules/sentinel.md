## 2024-05-24 - Fix TOCTOU DoS vulnerability in size limit checks
**Vulnerability:** File size limits used `path.stat().st_size` (or `DirEntry.stat().st_size`) followed by `open()` and `read()`. If an attacker replaces the file with a symlink to a massive file (e.g., 10GB) *after* the `is_symlink()` and `.stat()` checks but *before* `open()`, the open operation will follow the symlink and load the massive file into memory, causing a Denial of Service (OOM/CPU exhaustion). Using `follow_symlinks=False` on `stat` does not fix this, as it only measures the symlink itself (which passes the check) while the subsequent `open()` still follows it to the massive target.
**Learning:** Checking file properties via path prior to opening a file introduces a Time-Of-Check to Time-Of-Use (TOCTOU) race condition when symlinks are involved. `open()` inherently follows symlinks in Python.
**Prevention:** Always verify file attributes like size *after* opening the file by using `os.fstat(file_object.fileno()).st_size`. This securely queries the exact inode that was opened, preventing symlink hijacking between the check and use phases.
