## 2023-10-24 - [Secure Log File Truncation to Prevent TOCTOU]
**Vulnerability:** A TOCTOU (Time-of-Check to Time-of-Use) vulnerability existed when enforcing log file size limits, because `path.stat().st_size` was checked before renaming or accessing the log file, leaving a window for an attacker to hijack the file with a symlink.
**Learning:** Enforcing file size limits prior to unbounded file reads or writes is essential to prevent DoS. However, using `.stat().st_size` on an unopened path creates a TOCTOU race condition. Secure file truncation or log rotation can be achieved without `.stat()` or `.rename()` by using atomic file replacements (`tempfile.mkstemp` and `os.replace`), and only copying the original contents into the temporary file if the original file's size, checked via the safely opened file descriptor (`os.fstat(fd).st_size`), is under the limit.
**Prevention:** Always enforce a file size limit check before loading or parsing unbounded files. To avoid TOCTOU symlink vulnerabilities during this check, open the file first and evaluate its size via the file descriptor (e.g., `os.fstat(f.fileno()).st_size > limit`) rather than using `path.stat().st_size` before opening. If log truncation is needed, avoid using `path.rename()` and instead omit copying the file's contents during the atomic swap if it exceeds the limit.
